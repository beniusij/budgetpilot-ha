# Changelog

## [0.4.60] — 2026-11-06

### Added

- **Search your auto-categorisation rules.** Settings › Rules has a search box: type a merchant word or a category name to see only the rules that mention it, such as every rule that uses "tesco" or every rule filing into Groceries. Capitals don't matter and part of a word is enough. The rules keep their order, which is the order an import tries them, and a count shows how many of your rules match. Type a transaction's description, such as "AMEX TRAVEL FLIGHTS", and the search also shows every rule that could file it, in the order an import tries them, so you can see which one gets there first. You can drag or arrow-key a rule while searching: it moves just above or below the rule you drop it on, and the rules the search hides keep their order. Edits, copies and deletes made while searching are saved with the rest of your list, the rules the search hides included. Adding a rule clears the search, so you see it at the bottom of the list, where an import tries it last. Press ⌘F or Ctrl+F to jump to the box.

### Fixed

- **Switching a statement row between Shared and Personal keeps its category.** In the import review, changing a row from Shared to Personal (or back), on its own or with "Set all", used to clear its category when the category belonged to the other side, so a card payment filed as Transfers came up empty. The row is now filed as it would have been had it been imported on that side: your own rules run again for it, a category you chose yourself moves to the one of the same name, and a row with no match is left for you to pick as before.
- **Marking saved transactions personal or shared keeps their category.** On the Transactions page, "Mark personal" or "Mark shared" used to send any row whose category belonged to the other side to be re-filed by hand, so a card payment filed under the household's Transfers had to be picked again. It now moves to your own category of the same name on the new side, such as your personal Transfers, in the same save as the switch. Only a row with no category of that name is left for you to pick, as before. Your rules are not run again on saved transactions.
- **A transaction made personal no longer counts towards a shared goal.** Marking a shared transaction personal, on the Transactions page or in its edit window, used to keep its tag to a shared goal. That goal then showed the money as saved on your Goals page but not on your partner's, so you each saw different progress for the same goal. The tag is now removed in the same save, and both of you see the same figure. A tag to one of your own goals stays. Marking the transaction shared again does not put the tag back: assign it to the goal again if the money did go into the shared pot.
- **A transaction only counts towards a goal on its own side.** A shared transaction now counts only towards a shared goal, and a personal one only towards one of your own goals, so everyone who can see a goal sees the same saved figure. Making one of your transactions shared removes its tag to your own goal. "Assign to goal" turns down a goal on the other side and says how many transactions it couldn't assign. A statement row you switch to the other side in the import review is no longer tagged to a goal that doesn't fit, and is tagged again if you switch it back. A goal marked achieved stays achieved, and its saved figure moves by the amount of the transaction that left it. A shared transaction on a personal account doesn't count towards a shared goal either, since the other member can't see it; personal transactions on a joint account still count towards their owner's goals. Tags already saved on the wrong side are removed once, when you first open this version, closed months included, so a goal's saved figure can move by those transactions' amounts. Transactions from before splits existed keep their tags.

### Internal

- **The roadmap records that categories now survive a switch between Shared and Personal, goals count only transactions on their own side, and rules can be searched.**
- **The roadmap and product notes record that deleting an investment now deletes its trades.** The investments page note explains why a delete is refused when someone else holds the same investment in their own account.
